# Workflow: El Peruano Scraper

## Objective

Read the day's normas published in *El Peruano* (the primary source) and surface any that touch a tracked commitment as GitHub issues for editorial review. The reader never changes a status: `src/data/tracking.json` is only updated by a human through the PR flow.

El Peruano is the primary-source, high-precision stream feeding the `evidencia-candidata` queue: it *matches* each norma against the plan's own commitments via the shared `matcher.py` (below).

## How it works

1. `.github/workflows/elperuano-scraper.yml` runs daily (13:00 UTC ≈ 08:00 Lima) or on manual dispatch.
2. `tools/scrapers/elperuano_scraper.py` runs three stages:
   - **Fetch** — GET the public search page `https://busquedas.elperuano.pe/?fechaIni&fechaFin&tipoPublicacion=<NL|BO|PC|EX>&ci=ONLY&start`, paginated 20 cards/page across the day's four editions. Each server-rendered result card is parsed into `{tipo, numero, sector, sumilla, url, op, …}` (`url` is the norma's `/dispositivo/<tipoPub>/<op>` page).
   - **Match against plan commitments** — each norma's `numero + tipo + sumilla` is matched by the shared `tools/scrapers/common/matcher.py` against `commitment_index.json`, a distinctive-**bigram** index built from all 764 plan commitments (see below). A norma matches a commitment when it contains one of that commitment's distinctive bigrams. A day with zero matches ends the run.
   - **Issues + archive** — one `evidencia-candidata` issue per surviving candidate (stateless `[np-<sha1>]` dedup token in the title, cap 10/run), also labeled `tema:<slug>` per matched commitment so a tema's queue is one GitHub filter. Each issue embeds a text excerpt of the norma plus a ready-to-complete evidence JSON block. Text source: the `/dispositivo/<tipoPub>/<op>` page embeds the clean single-norma rendition in a `#visor-html` box (the same document the retired `/api/visor_html` endpoint served), stdlib-stripped; falls back to the sumilla when unavailable. The day's full record set is appended to `normas/<date>.jsonl` on the `normas-archive` branch (a growing structured corpus for future analysis — not read by anything yet).

   There is **no AI stage** (a Claude judge existed briefly and was removed 2026-07-15 — decision: no API costs; deterministic scrapers + human review are enough).

## The commitment matcher

`matcher.py` is shared (the only place matching logic lives; any future source uses it). Its index is built from the plan, not hand-written:

- `tools/scrapers/build_commitment_index.py` reads `src/data/plan/` (proposals + first-100-days + goals) and writes `commitment_index.json`: for each commitment, the **bigrams** (adjacent significant-word pairs) that are rare across the other commitments (`DF_MAX_BIGRAM`). Regenerate it whenever the plan changes: `python3 -m tools.scrapers.build_commitment_index`. CI runs `--check` to fail if the committed file drifts from the plan.
- **Why bigrams only:** a single word rare in the plan ("fiscal", "horario") is still common in daily normas, so unigram matching floods the queue. Multiword phrases ("unidades flagrancia", "ventanilla consular") are the precise signal. Matching is on filtered-token subsequences, so `"unidades flagrancia"` still matches "unidades **de** flagrancia".
- `tools/scrapers/commitment_overlay.json` is the hand-tune layer:
  - `suppress_phrases` — generic government bigrams the plan-frequency can't catch (they appear once in the plan but constantly in normas: "poder judicial", "servicios publicos", "direccion general", …). This is the main precision knob; add offenders here.
  - `boost` — extra phrases per commitment, including distinctive **single words** (e.g. `c5i`), the only route by which a unigram matches.
  - `mute_commitments` — silence a noisy commitment id, or a whole tema id (`t1-1`).
  - `suppress_terms` — extra global stopwords dropped during tokenization.
- Precision reference: over 4 real days this yields ~5–13 matched normas/day out of 300–650 (favor precision; misses are acceptable and caught by the news watcher or manual review).

## Inputs / config

- `tools/scrapers/commitment_index.json` — generated from the plan; regenerate with `build_commitment_index.py` when the plan changes.
- `tools/scrapers/commitment_overlay.json` — hand-tune: `suppress_phrases`, `boost`, `mute_commitments`, `suppress_terms` (see the matcher section).
- `tools/scrapers/elperuano_scraper.py` → `SKIP_TIPOS` — norma types to drop outright (empty by default; add municipal/local types if local noise appears); `SUBNATIONAL_SECTOR_RE` — drops norms whose `sector` is a municipality or regional government from the review queue (a subnational own-act can't evidence the *national* plan); `AUTONOMOUS_SECTOR_RE` — same reasoning one level up, dropping own-acts of the autonomous control and judicial bodies (Contraloría, Poder Judicial, Ministerio Público, Cortes Superiores, JNJ) while deliberately keeping INEI/BCR/RENIEC/ONPE/JNE, whose statistics measure the metas 2031; both applied at the match stage, so those records still reach the archive; `EXCERPT_CHARS` — issue excerpt length.

## Tuning precision

When the daily queue is noisy, inspect a day (`--dry-run`) and either add the offending generic bigram to `suppress_phrases`, or `mute` a commitment/tema in the overlay. When a real match is missed, add a `boost` phrase to that commitment. No index rebuild is needed for overlay edits; rebuild only when the plan text changes.

**First ask whether the phrase is the problem or the *act* is.** If the noise shares a shape rather than a phrase — every candidate is an appointment, a travel permit, a monthly index — `suppress_phrases` is the wrong knob and will cost recall (see `is_routine_act` below). Add an act gate instead.

## Reviewing a candidate issue

**Spending is not evidence of a promise** (decided 2026-08-07). A budget act — a transferencia financiera, a convenio de apoyo presupuestario, a transferencia de partidas — is the government *operating*, not the government *fulfilling a specific commitment*, and it is discarded unless it plainly executes what a compromiso promises. The plan is written in normative and programmatic terms ("impulso de normativa", "creación de brigadas", "fortalecimiento de COPESCO") while El Peruano records money moving, so this class recurs daily: issues #269 (NEC/Compras MyPerú), #211 (MINCETUR → GORE Amazonas) and #275 (CAP al PP 0057) were all real acts of this government, on tracked themes, evidencing nothing. **The queue is supposed to stay near-empty until a normative act appears** — an empty day is the system working, not a bug to tune away. Close these as «no acredita avance», never as «no tiene relación»: the match may be perfectly correct.

1. Read the norma (excerpt in the issue; full document via the El Peruano link) and confirm it actually cumple/avanza the compromiso.
2. If it holds: update `src/data/tracking.json` (status + evidence + log) on a `fix/` branch, `npm run validate`, PR, merge. The issue contains a ready-to-complete evidence block — write the `note` yourself.
3. Close the issue linking the PR, or with a comment explaining the discard.

## Known constraints / lessons

- The search page is **unofficial** and its markup can change. **History:** El Peruano exposed an unauthenticated GraphQL API (`/api/graphql`, `getGenericPublication`) until ~2026-07-26, when the site was rebuilt as a React Router app and that endpoint was removed (`404`) — the scraper failed daily 07-26…07-31 until repointed at the public search page (2026-07-31). If the card markup or the `?fechaIni&fechaFin&tipoPublicacion&start` params change, the run fails loudly in Actions — fix the parser in `parse_search_cards` and record the change here.
- **Pacing:** gazette requests go through a shared `REQUEST_DELAY` (0.8s) in `elperuano_client`. A day's sweep is ~60 search pages plus one `/dispositivo/` per candidate norma, and unpaced the site answers 404 and then drops the TLS connection. It reads as a slow failure, not a refusal, which is how it hid: fetching the 2026-07-28 cabinet, 4 of 38 normas came back and the other 34 fell back to their sumilla — and a sumilla names an office but never a person, so the sweep reported them as unreadable normas rather than requests that were never answered. Norma bodies retry like search pages do; they are the bulk of a sweep's requests and used to get one attempt each.
- **Editions:** the day's normas are split across four `tipoPublicacion` values — `NL` (Normas Legales), `BO` (Boletín Oficial), `PC` and `EX` (Edición Extraordinaria) — so the fetch loops all four and de-dups by `op`. **`EX` is where a change of government is published**, not `NL`: on 2026-07-28 the whole cabinet ran in `EX` (19 nombramientos, R.S. 223–241-2026-PCM, plus 19 renuncias, 204–222) while `NL` carried five records. It was missing from the loop until 2026-07-31, and the cabinet sweep reported zero appointments for a cabinet sworn in three days earlier. `EX` answers 200 with zero cards on days with no extraordinary edition, so it needs no special casing. Verified 2026-07-31: the search page reproduces the 07-25 archive (183/183 real normas; the only diff was 2 op-less records in the old GraphQL data).
- **Norma text:** the `/dispositivo/<tipoPub>/<op>` page inlines the clean single-norma HTML in a `#visor-html` box; its `<head>` `<title>` belongs to a neighboring norma, so `html_to_text` strips the head. No PDF path anymore (the old per-norma `urlPDF` proxy is gone) — text extraction falls back to the sumilla when the box is absent.
- 483 normas on a sample day (2026-07-10), most municipal; the matcher's bigram index + `suppress_phrases` stoplist are what keep the queue relevant.
- **Punctuation used to stick to tokens** (fixed 2026-08-02). `normalize` folds case and accents but not punctuation, so `"nacional,"` and `"nacional"` were different words and one phrase reached the index as several variants sharing its document frequency — `"nivel nacional"` arrived as three entries of DF 7/2/3, each under the `DF_MAX_BIGRAM` (12) gate that exists to drop exactly that. 3901 of 10480 bigrams carried punctuation. It cost recall too: a norma writing `"unidades de flagrancia,"` never matched the indexed `"unidades flagrancia"`. `significant_tokens` now splits on non-alphanumerics, so the matcher and the index builder stay symmetric. Replaying the 20-day archive (6573 records), the queue went 169 → 224: the fix **recovers** genuine matches punctuation had been dropping, so expect a slightly fuller queue, not an emptier one. Keep the fix in `significant_tokens`, not `normalize` — the latter also backs name folding in the jne/infobae rules and the ultimitas keyword filter, which are not phrase matching.
- **Autonomous bodies are out of scope** (`AUTONOMOUS_SECTOR_RE`, added 2026-08-02). The plan is the *executive's*, so a Contraloría registry annex, a fiscal appointment or a judge's destitution can't evidence it — five of the eight false positives on 2026-08-01/02 (issues #231–#235) came from exactly these publishers. **INEI, BCR, RENIEC, ONPE and the JNE are deliberately left in scope**: the 65 metas 2031 are quantitative and those bodies publish the statistics that measure them. INEI's statutory monthly price indices are handled on the phrase gate (`"nivel nacional"`) instead — do not "simplify" this by blocking INEI wholesale.
- **Routine acts are gated by what the norma does** (`is_routine_act`, added 2026-08-05). Two consecutive full queues — issues #246–#255 and #256–#265 — were 20/20 false positives, and every one was an appointment ("Designan Viceministro…", "Aceptan renuncia de…"), a travel/academic authorization, or a periodic index. The cause is structural: a commitment's distinctive bigrams come from the **entity's name** (`desarrollo pesquero` → FONDEPES, `gestion publica` → PCM, `infraestructura educativa` → PRONIED), so every routine act of a topically relevant body carries them. `suppress_phrases` cannot fix this — those phrases are the meaningful ones, and suppressing them would blind the matcher to the real norma when it comes. Note `"autoridad nacional"` was already suppressed and both ANA appointments still got through on other bigrams; that is the tell that the phrase layer was the wrong place. **The personnel rule deliberately spares collective objects**: "Designan a los integrantes de la Comisión Multisectorial encargada de X" creates the body that executes a commitment and is genuine early evidence. Do not widen it into a blanket verb match. **The exception needs both halves** — a collective noun (`integrantes|miembros|representantes|vocales`) *and* a task body (`comision|grupo de trabajo|mesa de trabajo|comite`) — and each half is there because the other one alone failed: `"miembros"` by itself let "Designan miembros del **Directorio** del BCRP" through (issue #268, ordinary churn on a standing board), and `"comision"` by itself waves through "Designan Presidente Ejecutivo de la **Comisión** de Promoción del Perú", because that is PROMPERÚ's registered name.
- **An autonomous body's own organs publish under their own names** (fixed 2026-08-06). `AUTONOMOUS_SECTOR_RE` was anchored with `^`, so "Autoridad Nacional de Control del Ministerio Público" — the MP's internal control authority, publishing its own budget acts — sailed past a gate written for exactly that (issue #271). It now matches anywhere in the sector: a sector string names the publisher, so containing one of these means the publisher *is* that body or an organ of it.
- **The Boletín Oficial emits section headings shaped like records** (`is_norma_record`, added 2026-08-06). "Balance Por Entidades Financieras" and "Estudios Ambientales (suelo, agua, ruido…)" arrive with no `numero` and no `sumilla`, so the matcher sees only the *tipo* — a section name — and matches on whatever topic words it contains (issue #272). Records with no sumilla are not normas; they still reach the archive.
- **The plan and the gazette name the same instrument differently — that is a recall bug, not noise** (issue #269, 2026-08-06). PRODUCE funded the *Núcleo Ejecutor de Compras* for textil-confecciones; the plan calls that mechanism **Compras MyPerú** (`t2-1.P22`), so the norma that funds the commitment shared **no bigram** with it and matched only `t3-2.P32` — a *schooling* commitment — on the generic `sector productivo`. The queue had the right norma under the wrong compromiso, which a reviewer following the `tema:educacion` label would have discarded. Fixed with `boost`, which is what that layer is for. Measure before boosting: `nucleo ejecutor` occurs **once in 8390 archived records** (24 days), so it costs no precision. **When triage says "relevant, wrong compromiso", reach for `boost`, not `suppress_phrases`** — and check the archive for the phrase's frequency first.
- **Sequencing lesson.** Fixing the act gate first was what made the rest legible: the personnel flood was drowning four unrelated defects, and only once it was gone did they show up as one issue each. Expect the same again — when the queue is uniform, fix the shape; when it is five different wrongs, fix them one at a time. Three days replayed after both rounds: 326/742/223 normas → **1 candidate each**.
- **Plan toponyms collide with court names.** `"santa rosa"` and `"jorge chavez"` are airports in the plan's airport-modernisation proposal; in El Peruano they are overwhelmingly the names of *courts*, which publish far more often than airports get modernised. Both are suppressed; a genuine airport norma still carries `"aeropuertos concesionados"`. Expect more of this class — suppress the toponym, and assert the commitment still matches on its subject-matter phrase.
- **Replay the whole issue corpus before widening a gate** (2026-08-11). Issue #289, "Nombran Cónsul General del Perú en Orlando", matched three PEX commitments on `consulados` and `Estados Unidos` — the entity-name collision again, and `Nombran` was simply a verb the gate had never been burned by. Rather than add the one verb, every past candidate was replayed through the current gates (`gh issue list --state all` → `is_norma_record` + `in_national_scope` + `is_routine_act`), which showed **five** still-reachable churn acts in three shapes, including **both ends of the same consular rotation**: "Dan por terminadas las funciones de Cónsul General del Perú en Orlando" (issue #52) and, two months later, the naming of the replacement. A gate patched one incident at a time only ever learns the verb that just burned it; the corpus shows the family. Then diff old-vs-new across the corpus and confirm **every** changed verdict is churn — the fix here moved exactly 6 of 197 and no substantive act.
- **Widen the verb, anchor the object.** Each addition in that round is deliberately bounded, because the bare verb is not always routine: `dan por concluido` governs the *Régimen de Contingencia* in issue #271, a substantive act, so the pattern requires a `designación` or `funciones`; and **`delegan facultades` is also how Congress hands legislative power to the Executive** — the most consequential act the gazette carries — so it gates only when the delegation runs *down* to an entity's own `servidores`/`funcionarios` (issues #80, #81). Both bounds have a test asserting the substantive twin still reaches the queue.
- **A draft is not evidence** (`_DRAFT_RE`, added 2026-08-13). A prepublicación, a *proyecto* put out for comment, or a difusión en consulta pública is a text **not in force** — it cannot evidence a commitment, and the same instrument returns as its own candidate when it is finally enacted, so gating the draft costs no recall. Zero of the plan's 699 commitments name a draft as their target. Three landed in one queue (issues #295, #302, #303) and four more were closed by hand before it (#83, #128, #134, #139). The paired test asserts the *enacted* version of the same instrument still reaches the queue — that is the property that makes this gate safe.
- **Statutory determinations are the Cultura equivalent of a designación** (`_HERITAGE_DECLARATION_RE`, added 2026-08-13). Under Ley 28296 the Ministerio de Cultura declares objects, archives and expressions Patrimonio Cultural de la Nación continuously; **three arrived in a single queue** (issues #298–#300, all matching `t3-2.P35`). Checked before gating: `patrimonio cultural` appears in exactly one commitment, and P35 promises *promoción de la economía naranja* and Escuelas Técnicas — not the declarations themselves. Same shape as the personnel flood: a routine statutory function of a topically relevant body, carrying that body's name-bigrams.
- **Gate the hazard formula, never the phrase «estado de emergencia»** (2026-08-13). Issue #301 declared emergency in sixteen departments for déficit hídrico — routine SINAGERD/INDECI risk management, and it matched *voluntariado jurídico* and *tráfico de madera*. But the plan **promises an emergency**: `t1-1.P18` is a Plan de Emergencia against inseguridad ciudadana via delegación de facultades legislativas por 60 días. So the gate fires only on the Ley 29664 wording (`peligro inminente`, `desastre`, `impacto de daños`) and a security emergency keeps its place, with a test asserting exactly that. **P18 is also why `delegan facultades` was anchored to `servidores` the week before** — the plan cares about legislative delegation, and a blanket verb gate would have swallowed the very norma that proves it.
- **A multi-word `boost` used to leak its individual words into the index** (fixed 2026-08-17). `load_matcher` expanded each boost phrase with `phrases_of()`, which returns *unigrams plus bigrams* — so boosting `"ejecutor compras"` for Compras MyPerú (2026-08-06) also indexed a bare **`compras`**, plus `nucleo` and `ejecutor`. PERÚ COMPRAS puts that word in the **`numero`** of every resolution it publishes (`RESOLUCIÓN JEFATURAL N° 000097-2026-PERÚ COMPRAS-JEFATURA`), and the matcher reads `tipo numero sumilla` — so the agency's entire output matched `t2-1.P22` permanently (issues #316, #317), and `ejecutor` caught every Ejecutor Coactivo designation besides. The fix keeps a **one-token** boost as a unigram — `c5i` is the reason this layer accepts single words at all — and reduces anything longer to its adjacent bigrams, which is precisely what a norma yields. The regression test that matters is that the NEC norma the boost exists for (issue #269) still matches. **Lesson: a `boost` is authored as the phrase it means; only that phrase belongs in the index.** Watch for the same shape in reverse — a norma's `numero` is matched text, not metadata, so agency names embedded in resolution numbers are a live source of collisions.
- **Match breadth looked like a filter and was left alone** (measured 2026-08-17). Issue #322, a SUNEDU TUPA modification, matched **11 commitments across 7 temas** on `procedimientos administrativos` and `educacion superior`; across the archive, 52% of queued normas match a single tema and only 12% span four or more, which makes a breadth threshold tempting. Not implemented, for two reasons. The 4+ group is **contaminated**: most of it is pre-2026-07-26 records whose numeric `sector` the scope gate cannot read (see below), so they are municipal ordinances that would be dropped today anyway. And the risk runs the wrong way — a genuinely major reform (a Política Nacional, a broad Decreto Supremo) is exactly the norma that legitimately touches several temas, so the heuristic would suppress the most consequential evidence first. Revisit only with clean post-format data.
- **Archive records before 2026-07-26 carry a numeric `sector`** (`95`, `1373`, `9316`) — a leftover of the old GraphQL feed, ending 2026-07-25. `in_national_scope` reads the sector as a name, so for those days it silently passes everything, municipalities included. **Any replay over the archive that spans that boundary will over-report what reaches the queue**; scope-sensitive audits should start at 2026-07-26 or later. Not a live bug — the search-page format has carried real sector names since.
- **The scraper cannot answer "has promise X moved?"** — it indexes the whole plan and asks of each norma *which commitment does this resemble?*, so a promise nobody legislated on simply never comes up, and its silence is indistinguishable from the scraper not running. `tools/plan/audit_100_days.py` asks the inverse, one promise at a time: each first-100-days action gets a hand-authored probe (`hundred_days_probes.json`, usually the branded programme name — if `FEDETUR` existed, that string would be in its creating norm) and the whole archive since the inauguration is swept for it. Run it to answer "where do the 100 days actually stand?"; every `.C` id must have a probe or the audit fails, so a regenerated plan cannot silently lose coverage. **First run, 2026-08-13 (16 days in, 6209 normas): 58 of 67 actions with no trace at all, and the 9 with hits were probe collisions** — JNE rulings from the *Jurado Electoral de Tumbes*, COFOPRI staff appointments. The closest thing to evidence was an EJE expansion by the *Poder Judicial* under a programme running since 2017: wrong actor, pre-existing, one courtroom against a promise of *todos los distritos judiciales*.
- **Report the coverage limit, not just the count.** Only ~15 of the 67 hundred-day actions promise something that cannot exist without a published norm (`Publicación de`, `Creación de`, `Emisión de Decretos de Urgencia`). The rest are campaigns, operativos and deployments that never touch the gazette, so for them an empty result means nothing at all. The audit prints both numbers and the site carries the caveat in prose on `/primeros-100-dias/` — deliberately **without** the 15/67 figure, because that split is a regex over the promise's leading verb and a floor, not a measurement. Keep heuristics in the tool and qualitative statements on the page.
- **Name each periodic series, and anchor the ones the plan cares about** (2026-08-19). `_RECURRING_INDEX_RE` started as two series and needed two more: INEI's monthly *Factores de Reajuste* for construction, which matched **ten commitments across nine temas** (issue #333) on nothing but construction and geography words, and the MEF's *Índices de Distribución* of canon and regalía, which a single new district is enough to re-trigger (issue #332). These are calendar publications carrying no policy, and their fan-out is the worst in the queue. The canon half is anchored: the plan **does** want canon reform — `t2-2.P17` promises "Canon para el Pueblo", up to 40% redistributed to the extraction zone — but that changes the *rule* and would arrive as a Ley or Reglamento, while these resolutions apply the rule that already exists. Third time this distinction has decided a gate, after `estado de emergencia` and INDECOPI's barreras burocráticas: **gate the periodic execution, never the rule.**
- **The check that makes a class gate safe.** Before gating any act type, grep the 699 commitments for the phrase and read what the hits actually promise. Twice now the plan turned out to promise the *outcome* while the gazette publishes the *routine instrument* (patrimonio, emergencia), and once it promised the instrument itself (`t1-1.P18`) — which is the case that decides between a phrase gate and an anchored one.
- **Noise classes now closed** (all were open when the archive was replayed on 2026-08-02): personnel churn ran ~25 of 224 queue entries and is gated by `is_routine_act`, whose verb list now covers `designan`/`nombran`/`proclaman`/`encargan`/`acreditan`/`formalizan`, the renuncia, conclusión and terminación forms, staff delegations, and `autorizan viaje`; extraditions and single-case regulator adjudications (INDECOPI barreras burocráticas, OSIPTEL mandatos de compartición) are gated too; `Boletín Oficial` listing rows — empty `sumilla`, a title fragment in `tipo`, sometimes a numeric `sector` (`95`, `9588`) that no sector gate can read — are gated by `is_norma_record`. What remains in the queue is register mismatch, not act type: see the spending criterion above.
- Issues created by `GITHUB_TOKEN` don't trigger other workflows (GitHub policy) — irrelevant here.
- The archive push goes through `tools/ci/publish_data_branch.sh` (shared with the ultimitas scraper): a `git worktree` on the orphan `normas-archive` branch, so it never touches `main` (which is protected by the `protect-main` ruleset).
